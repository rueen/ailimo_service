# 笼位房间相关变更说明（管理端）

> 本文档仅描述**笼位房间**相关的接口与数据变动，供前端对接使用。具体实现由前端自行完成。

---

## 一、新增：笼位房间管理

以下接口为**新增**，需前端新增对应页面/模块。

| 接口 | 方法 | 路径 | 说明 |
|------|------|------|------|
| 笼位房间列表 | GET | `/api/support/cage-rooms` | 分页列表，支持 `name` 模糊筛选 |
| 创建笼位房间 | POST | `/api/support/cage-rooms` | 请求体：`name`（必填） |
| 更新笼位房间 | PUT | `/api/support/cage-rooms/:id` | 请求体：`name`（可选） |
| 删除笼位房间 | DELETE | `/api/support/cage-rooms/:id` | 有笼位时不可删除 |

- 列表项结构：`id`、`name`、`created_at`（及部分接口含 `updated_at`）。
- 权限：列表 `cage_room:list`，创建 `cage_room:create`，更新 `cage_room:update`，删除 `cage_room:delete`。

## 二、笼位管理接口变动

### 2.1 笼位列表 `GET /api/support/cages`

- **响应变动**：每条笼位项增加 `room` 对象（可为 `null`）。
  - `room`: `{ "id": 1, "name": "101房间" }`

### 2.2 笼位详情 `GET /api/support/cages/:id`

- **响应变动**：增加 `room` 对象（可为 `null`）。
  - `room`: `{ "id": 1, "name": "101房间" }`

### 2.3 创建笼位 `POST /api/support/cages`

- **请求变动**：增加参数 `room_id`（房间 ID）。
- **响应变动**：返回数据中增加 `room_id`。

### 2.4 更新笼位 `PUT /api/support/cages/:id`

- **请求变动**：增加参数 `room_id`。

### 2.5 根据动物类型和环境类型获取房间选项 `GET /api/support/cages/rooms-by-animal-type-and-environment`

- **新增接口**：用于获取指定动物类型和环境类型下有笼位的房间列表。
- **请求参数**：
  - `animal_type_id`（必填）：动物类型 ID
  - `environment_id`（必填）：环境类型 ID
- **响应结构**：`[{ "id": 1, "name": "101房间" }, ...]`
- **用途**：前端在用户选择动物类型和环境类型后，调用此接口获取可选房间列表。
- **权限**：已登录即可。

### 2.6 查询笼位剩余可用数量 `GET /api/support/cages/available-quantity`

- **请求变动**：增加参数 `room_id`。

## 三、笼位预约订单接口变动

### 3.1 笼位预约订单列表 `GET /api/support/cage-reservations`

- **响应变动**：每条预约项增加 `room` 对象（可为 `null`）。
  - `room`: `{ "id": 1, "name": "101房间" }`

### 3.2 笼位预约订单详情 `GET /api/support/cage-reservations/:id`

- **响应变动**：
  - 顶层增加 `room`: `{ "id": 1, "name": "101房间" }`（可为 `null`）。
  - `cage` 对象内增加 `room`: `{ "id": 1, "name": "101房间" }`（可为 `null`）。

### 3.3 新增笼位预约订单 `POST /api/support/cage-reservations`

- **请求变动**：增加参数 `room_id`（房间 ID）。
- **响应变动**：返回数据中增加 `room_id`（可为 `null`）。

### 3.4 编辑笼位预约订单 `PUT /api/support/cage-reservations/:id`

- **请求变动**：增加参数 `room_id`。
