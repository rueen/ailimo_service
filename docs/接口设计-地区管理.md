# 地区管理接口文档

## 概述
本文档定义地区管理相关接口，用于提供省市区三级联动数据。

**说明**：地区数据为公共数据，管理端和用户端使用相同的接口。

**接口路径**:
- 管理端：`/api/support/regions`
- 用户端：`/api/h5/regions`

---

## 1. 地区列表

### 1.1 获取地区列表
**接口地址**: 
- 管理端：`GET /api/support/regions`
- 用户端：`GET /api/h5/regions`

**请求参数**:
| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| parent_id | number | 否 | 父级地区ID，0或不传表示获取省级列表 |
| level | number | 否 | 地区层级：1=省，2=市，3=区 |

**请求示例**:
```bash
# 获取所有省份
GET /api/h5/regions?level=1

# 获取某省下的所有市
GET /api/h5/regions?parent_id=440000&level=2

# 获取某市下的所有区
GET /api/h5/regions?parent_id=440300&level=3
```

**响应数据**:
```json
{
  "code": 200,
  "message": "success",
  "data": [
    {
      "id": 1,
      "name": "北京市",
      "code": "110000",
      "parent_id": 0,
      "level": 1,
      "sort_order": 1
    },
    {
      "id": 2,
      "name": "天津市",
      "code": "120000",
      "parent_id": 0,
      "level": 1,
      "sort_order": 2
    }
  ]
}
```

**说明**: 
- 不传参数时，默认返回所有省份（level=1）
- `code` 为行政区划代码（省6位，市6位，区6位）
- 返回数据按 `sort_order` 排序

## 2. 地区详情

### 2.1 获取单个地区详情
**接口地址**: 
- 管理端：`GET /api/support/regions/:id`
- 用户端：`GET /api/h5/regions/:id`

**路径参数**:
| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| id | number | 是 | 地区ID |

**响应数据**:
```json
{
  "code": 200,
  "message": "success",
  "data": {
    "id": 3233,
    "name": "南山区",
    "code": "440305",
    "parent_id": 440300,
    "level": 3,
    "sort_order": 5,
    "status": 1
  }
}
```

## 3. 使用场景

### 3.1 三级联动选择
前端实现省市区三级联动的典型流程：

```javascript
// 1. 页面加载时，获取省份列表
GET /api/h5/regions?level=1

// 2. 用户选择省份后，获取该省的市列表
// 假设选择了广东省（id=19, code=440000, name='广东省'）
GET /api/h5/regions?parent_id=440000&level=2

// 3. 用户选择城市后，获取该市的区列表
// 假设选择了深圳市（id=203, code=440300, name='深圳市'）
GET /api/h5/regions?parent_id=440300&level=3

// 4. 用户最终选择了"南山区"（id=3233, name='南山区'）
// 提交用户注册或订单时，传递地区名称
{
  "province": "广东省",
  "city": "深圳市", 
  "district": "南山区"
}

// 注意：当前系统设计中，用户表和订单表存储的是地区名称（字符串），而非ID
// 这是为了保证数据的历史一致性（即使未来地区调整，历史数据也能正确显示）
```

### 3.2 显示完整地区路径
前端可以通过地区ID获取详情，显示完整地区路径：

```javascript
// 假设用户表中存储了 province_id=19, city_id=203, district_id=3233
// 前端可以分别调用获取详情接口，或者在列表查询时就获取了完整信息

// 显示：广东省 / 深圳市 / 南山区
```

## 4. 数据说明

### 4.1 数据来源
- 使用开源项目 **modood/Administrative-divisions-of-China** 的数据
- 数据基于国家统计局最新行政区划
- 包含全国34个省级行政区、300+地级市、2800+区县

### 4.2 数据更新
- 数据相对稳定，通常每年更新1-2次
- 如需更新，可直接替换 regions 表数据

### 4.3 行政区划代码说明
- 省级：6位，后4位为0（如：北京市 110000）
- 市级：6位，后2位为0（如：深圳市 440300）
- 区级：6位（如：南山区 440305）

## 6. 注意事项

1. **缓存建议**：地区数据变化频率很低，建议前端做本地缓存（如 localStorage），有效期可设置为7天或更长
2. **性能优化**：后端也建议对地区数据做 Redis 缓存，提升查询性能
3. **数据量**：全国约3200个区县，单次查询返回数据量不大，无需分页
4. **状态字段**：`status=0` 表示该地区已禁用（如行政区划调整），前端应过滤或标记
5. **存储方式说明**：
   - 当前系统的用户表（`users`）和订单表（`animal_orders` 等）存储的是**地区名称字符串**，而非地区ID
   - 这样设计的好处是数据历史一致性好，即使未来地区调整，历史数据也能正确显示
   - 前端在提交表单时，应将用户选择的地区名称（`name` 字段）提交到后端
   - 示例：`{ "province": "广东省", "city": "深圳市", "district": "南山区" }`

## 7. 与现有表的关系

### 7.1 用户表（users）
用户注册时需要选择省市区：
- `province` VARCHAR(50) - 存储省份名称
- `city` VARCHAR(50) - 存储城市名称
- `district` VARCHAR(50) - 存储区县名称

### 7.2 动物订购订单表（animal_orders）
动物订单的收货地址需要省市区：
- `province` VARCHAR(50) - 收货省份
- `city` VARCHAR(50) - 收货城市
- `district` VARCHAR(50) - 收货区县
- `address` VARCHAR(200) - 详细地址

### 7.3 前端使用建议
```javascript
// 用户选择地区后
const selectedProvince = { id: 19, name: '广东省', code: '440000' };
const selectedCity = { id: 203, name: '深圳市', code: '440300' };
const selectedDistrict = { id: 3233, name: '南山区', code: '440305' };

// 提交时只传 name，不传 id
const formData = {
  // ... 其他字段
  province: selectedProvince.name,  // '广东省'
  city: selectedCity.name,          // '深圳市'
  district: selectedDistrict.name   // '南山区'
};
```
