# 实验代操作统计功能 - 使用说明

## 📋 功能概述

该功能用于统计指定时间范围内，每天每个用户各种操作类型的动物数量，主要用于月底与用户结算代操作费用。

## 🚀 快速开始

### 1. 权限配置

首先需要运行权限生成脚本，确保权限已添加到数据库：

```bash
npm run generate-permissions
```

这将添加 `experiment_operation:statistics` 权限到系统中。

### 2. 为角色分配权限

登录管理后台，为需要查看统计数据的角色（如管理员、财务人员）分配以下权限：
- **代操作统计** (`experiment_operation:statistics`)


| 参数 | 类型 | 必填 | 说明 | 示例 |

| start_date | String | 是 | 统计开始日期 | 2024-12-01 |
| end_date | String | 是 | 统计结束日期 | 2024-12-31 |

### 数据字段说明

1. **dates** (Array): 日期数组
   - 包含从 start_date 到 end_date 的所有日期
   - 按升序排列
   - 格式：YYYY-MM-DD

2. **users** (Array): 用户数组
   - 只包含在此时间范围内有预约的已完成订单的用户
   - 按用户ID升序排列
   - 每个用户对象包含：
     - `id`: 用户ID
     - `name`: 用户真实姓名
     - `operations`: 该用户涉及的操作类型数组

3. **data** (Object): 统计数据对象
   - Key 格式：`{日期}_{用户ID}_{操作类型ID}`
   - Value: 该组合的动物数量总和
   - 只包含有数据的项（值为0的不返回）

## 💡 业务逻辑说明

### 统计规则

1. **只统计已完成的订单** (status = 3)
2. **按预约日期统计**（解析 time_slots 字段，提取预约日期）
3. **分组维度**：
   - 日期（预约日期，从 time_slots 中提取）
   - 用户ID
   - 操作类型ID
4. **汇总值**：每个分组的动物数量（quantity）总和

### time_slots 解析说明

- time_slots 格式：`["2026-01-22 09:00-12:00", "2026-01-22 13:00-18:00"]`
- 从每个时间段中提取日期部分（YYYY-MM-DD）
- 如果一个订单有多个预约日期，每个日期都会统计该订单的数量
- 只统计在查询时间范围内（start_date 到 end_date）的预约日期

### 数据过滤

- 只返回在指定时间范围内有预约的已完成订单的用户
- 每个用户只显示其实际操作过的操作类型
- 统计数据对象只包含有数据的键值对

### 用户信息扩展

返回的用户信息包含：
- 基本信息：id, name, user_no, phone
- 组织信息：organization（id, name）
- 学院信息：department（id, name）
- 课题组信息：research_group（id, name）
- 如果用户选择的是"其他"并手动输入，则显示用户输入的名称，id 为 null

### 数据渲染逻辑

```javascript
// 获取单元格数据
const getCellValue = (date, userId, operationId) => {
  const key = `${date}_${userId}_${operationId}`;
  return data[key] || ''; // 如果没有数据返回空字符串
};

// 计算列小计
const getColumnTotal = (userId, operationId) => {
  return dates.reduce((sum, date) => {
    const key = `${date}_${userId}_${operationId}`;
    return sum + (data[key] || 0);
  }, 0);
};

// 计算行合计
const getRowTotal = (date) => {
  let sum = 0;
  users.forEach(user => {
    user.operations.forEach(operation => {
      const key = `${date}_${user.id}_${operation.id}`;
      sum += (data[key] || 0);
    });
  });
  return sum;
};

// 计算总计
const getGrandTotal = () => {
  return Object.values(data).reduce((sum, value) => sum + value, 0);
};
```

## 🧪 测试场景

### 场景 1：基本统计

**前置条件**：
- 有多个用户
- 有多条已完成的实验代操作订单
- 订单在指定时间范围内

**测试步骤**：
1. 选择时间范围（如 2024-12-01 到 2024-12-31）
2. 调用统计接口
3. 验证返回的 dates 数组包含所有日期
4. 验证 users 数组只包含有已完成订单的用户
5. 验证 data 对象中的数据与数据库记录一致

### 场景 2：空数据处理

**前置条件**：
- 指定时间范围内没有已完成订单

**预期结果**：
```json
{
  "dates": ["2024-12-01", "2024-12-02", ...],
  "users": [],
  "data": {}
}
```

### 场景 3：参数验证

**测试用例**：
1. 缺少 start_date → 返回 400 错误
2. 缺少 end_date → 返回 400 错误
3. 日期格式错误 → 返回 400 错误
4. start_date > end_date → 返回 400 错误

## 🔧 性能优化建议

### 数据库索引

建议添加以下复合索引：

```sql
-- 实验代操作表
CREATE INDEX idx_experiment_operations_statistics 
ON experiment_operations(status, completed_time, user_id, operation_content_id);
```

### 查询优化

1. 限制时间范围（建议不超过 1 年）
2. 使用数据库层面的日期函数分组
3. 避免 N+1 查询问题

### 缓存策略

对于历史数据（已结束的月份），可以考虑缓存结果：

```javascript
// 示例：使用Redis缓存
const cacheKey = `stats:experiment:${start_date}:${end_date}`;
const cached = await redis.get(cacheKey);

if (cached) {
  return JSON.parse(cached);
}

const result = await getStatistics(start_date, end_date);

// 如果是历史数据，缓存1个月
if (end_date < today) {
  await redis.setex(cacheKey, 30 * 24 * 3600, JSON.stringify(result));
}

return result;
```

## 📝 常见问题

### Q1: 为什么某些日期没有数据？

**A**: 统计只包含已完成状态的订单。如果某天没有完成任何订单，该日期的统计数据为空。

### Q2: 如何导出Excel？

**A**: 前端使用 `xlsx` 库，将返回的数据组装成二维数组导出。详见文档中的导出说明。

### Q3: 统计数据不准确怎么办？

**A**: 检查以下几点：
1. 订单状态是否为"已完成"（status = 3）
2. completed_time 是否在查询的时间范围内
3. 是否有数据库索引，确保查询效率

### Q4: 能否按操作人员统计？

**A**: 当前版本按用户（user_id）统计。如需按操作人员统计，需要修改查询逻辑。
